# Вклад прямоугольных фрагментов

Сравнение полного генератора с режимом `--no-fault-dp`.
Локальный балл: меньше — лучше.

- Без DP: **22.285051125649**
- С DP: **22.285051099330**
- Снижение балла: **0.000000026319**
- Итоговых раскладок из DP: **1** (1 прямых, 0 после удаления)

## Фрагменты по распределённому выигрышу

`w×h+d` означает размеры фрагмента и число квадратов сверх `w·h`; `f` — его выступ за целочисленную рамку.
Выигрыш каждого `n` делится поровну между вхождениями фрагментов в его исходную цепочку. Это учётный вклад, а не независимый эффект замены одного фрагмента. Связанный выигрыш считает всю прибавку `n` для каждого фрагмента цепочки и поэтому не суммируется.
Уникальный максимум `f` показывает, где один фрагмент ограничивает порог цепочки; это подсказка для следующего поиска, не гарантия улучшения итоговой стороны.

| Фрагмент | f | n | Вхождений | Распределённый выигрыш | Связанный выигрыш | Уникальный максимум f | Размеры n |
|---|---:|---:|---:|---:|---:|---:|---|
| 8×25+8 | 0.746711 | 1 | 1 | 0.000000013 | 0.000000026 | 1 | 976 |
| 23×6+7 | 0.746671 | 1 | 1 | 0.000000013 | 0.000000026 | 0 | 976 |

## Кандидаты для следующего поиска

Фрагменты ниже чаще других одни задают максимальный `f` в используемых цепочках. Уменьшение их `f` стоит проверить в первую очередь; итоговый выигрыш нужно измерять новым полным прогоном.

- **8×25+8**: 1 случаев с единственным максимумом `f=0.746711`; используется в 1 итоговых раскладках.
- **23×6+7**: 0 случаев с единственным максимумом `f=0.746671`; используется в 1 итоговых раскладках.

## Итоговые раскладки с происхождением из DP

`Источник` — число квадратов при исходной сборке цепочки. Полный путь удаления записан в JSON.

| n | Источник | Шагов удаления | Сторона без DP | Итоговая сторона | Выигрыш балла | Фрагменты |
|---:|---:|---:|---:|---:|---:|---|
| 976 | 976 | 0 | 31.746712 | 31.746711 | 0.000000026 | 8×25+8, 23×6+7 |

Метод: для каждого `n` сравниваются стороны итоговых раскладок двух полных прогонов; разность баллов равна `(L_без_DP − L_с_DP)/√n`. Отчёт использует стороны в памяти до сериализации CSV и отдельно измеряет зафиксированные доказанные раскладки по их координатам.
